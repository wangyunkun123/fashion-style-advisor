## 五、关键问题与解决（9 个坑）

| # | 问题 | 根因 | 解决 |
|---|------|------|------|
| 1 | 图片不显示 | 路径前缀 `../outfits/` + URL 编码中文 | 改为 `outfits/` + `unquote()` URL 解码 |
| 2 | Hero 数据是旧的 | 静态 HTML 硬编码 | 构建时 `scan_outfits()` 动态注入数据 |
| 3 | 排版反复出错 | 修改了 CSS/HTML 结构 | 恢复确认版 commit `6b79bad`，**只改数据源** |
| 4 | 发送按钮消失 | 恢复版本时丢失 | 补回 `page-bottom` button HTML + JS |
| 5 | 换一批失效 | `refreshAlts` JS 函数丢失 | 补回完整函数 |
| 6 | 标签不一致 | API 和构建用不同逻辑 | 统一 `extract_tags()` 4 分类智能匹配 |
| 7 | Apple Watch 无表带 | `尼龙回环` 未匹配关键词 | 增加反向词序匹配 |
| 8 | 生成后不刷新 | 原型未重建 | 管线末尾自动运行 `build_prototype.py` |
| 9 | 旧样式覆盖 grid | 历史 CSS 残留 | 确认版 CSS 隔离，不动结构 |

## 六、建立的核心规则

### 6.1 原型排版铁律
- **一旦排版确认，只改数据源，绝不动 CSS 和 HTML 结构**
- 确认版 commit：`6b79bad`
- 记录在 `memory/prototype-layout-rule.md`

### 6.2 Hero 图规则
- 优先级：`上身效果_1.png`（AI 原始生图）> 人物图 > 排版图
- AI 生图完成后保留原始图，不删除
- 记录在 `memory/hero-image-rule.md`

### 6.3 管线重建规则
- 每次生成新穿搭后必须运行 `python3 tools/build_prototype.py` 重建原型
- `wechat_control.py` 从文件读取，所以必须先重建再刷新

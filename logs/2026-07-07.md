## 二、生图三 Bug 修复

### 2.1 连衣裙与上衣重复冲突（校验漏洞）
- **现象**：户外机能风同时选了上衣 TS-005 和连衣裙 PT-004（category=连衣裙/DRESS），重复且连衣裙生图未生效
- **根因**：`validate_outfit` 缺一体式单品（DRESS/SUIT/JMP）与独立上衣/下装的互斥检查
- **修复**（`tools/unified_pipeline.py` ~2466）：
  - 新增 `onepiece_count`（DRESS/SUIT/JMP）互斥：>1 报错
  - 一体式存在时禁止再叠独立上衣/下装
  - `top_count` 补入 KNIT/BLOUSE；`bottom_count` 补入 SKIRT
- **测试**：7 真实 + 4 逻辑用例全过，单连衣裙/正常上下装无误伤

### 2.2 摄影风格失效（HARD LOCK 改写）
- **现象**：法式/机能风生图的场景、相机、胶片全按豆包自己想象走，无视 `get_photo_direction` 给的塞纳河/Portra/巴黎场景
- **诊断**：端到端测试证明 photo_direction 正确且已注入（char 810），是 AI 指令遵循问题，非代码 Bug（Lost-in-the-middle）
- **修复**（三处硬约束改写）：
  - A. `get_photo_direction` 返回文案 → 「HARD LOCK — 必须忠实还原，不可替换」，场景/器材/光影标 🔒 硬性设定
  - B. seedream_prompt 字段说明 → 删「自然改写」，加「🔒场景锁定/器材锁定，只能润色英文措辞」
  - C. user_prompt 开头「北京天气」→「当前天气（天气只判断穿着舒适度，不是拍摄地点）」，消除场景锚点误导

### 2.3 生成失败 KeyError 崩溃
- **现象**：「雨天禁止皮质鞋」校验失败后，AI 纠正重选只返回 id/category/reason，缺 name/color → `execute_outfit_plan` 拼表 `it['name']` KeyError → 崩溃（此时 rmtree 已清目录，留下半损坏 outfit 目录，异常被吞无 ERROR 日志）
- **修复**（`tools/wechat_control.py` ~2810）：新增 `_item_field()` 兜底，缺字段时从服装档案回填 name/color/category

### 2.4 根因：运行中服务加载旧代码 ⚠️
- 手机连接的 daemon（--port 8765）不自动 reload Python 模块，命令行测试用新代码（正常）但手机走旧进程
- **教训**：改管线代码后必须 kill + 重启手机服务进程
- 详见 memory: `generation-crash-and-photo-lock-fixes.md`

# 开发日志 2026-06-21

## 连接修复 + 性能优化日 — 11 项改进

### 1. Tailscale Funnel 上传死机修复
- 服务器单线程 HTTPServer 被慢请求卡死，Funnel 进入降级状态
- 修复：强杀进程 + 重启服务 + `tailscale funnel off/on` 重置 Funnel
- 原因：POST 请求静默超时后，线程一直被占用

### 2. 批量分析同品类 ID 冲突修复
- 上传 2 张图同是长裤，`_get_next_id` 返回同一个 PT-007
- 第二件覆盖第一件标签，导致只入库一件
- 修复：分析阶段加 `assigned_ids` 集合 + `_id_exists_on_disk()` 双重去重
- 遗留图手动恢复为 PT-008

### 3. 入库并行化
- 确认入库串行 for → 多线程 `threading.Thread` 并行
- 共享文件加 `_wardrobe_lock`（`_append_to_wardrobe_md` + `_register_new_item` 整个读改写进锁）
- 两件 21s → ~11s

### 4. 图片缓存三件套
- **24h 浏览器缓存**：`Cache-Control: public, max-age=86400` + ETag（`mtime-size-w`）
- **25MB LRU 内存缓存**：`_image_cache_get/put`，`OrderedDict` + `_IMG_CACHE_LOCK`
- **600px 按需缩图**：`/api/image?w=600`，PIL LAN CZOS resize，体积减半

### 5. 浏览器缓存 ETag 自动刷新
- 首次返回 `ETag: "mtime-size-w"` + `Cache-Control: max-age=86400`
- 再次请求带 `If-None-Match` → `304 Not Modified`，零传输
- 文件修改后 mtime 变化 → ETag 不匹配 → 返回新内容 `200`
- 移除 `immutable` 指令（否则浏览器不会 revalidate）

### 6. 衣橱卡片 Date.now() 缓存破坏者移除
- `renderItemCard` 每次打开生成 `&t=Date.now()` → 新 URL → 浏览器永不缓存
- 去除后 ETag 接管失效检测，同一件衣服关闭再打开瞬间显示

### 7. Hero 服装卡片走 /api/image
- `data-cutout` 从相对路径 `../wardrobe/enhanced/xxx.png` → `/api/image?f=...`
- `showImg` 自动补 `&w=600`，享受缩图 + ETag 缓存

### 8. 历史卡片服装缩略图改 CDN
- `gen_history_card()` 原来优先 `/api/image`（Funnel 不可靠）
- 改为 CDN 缩略图 `_cutout_thumb.png`（CDN 确认可用）

### 9. 首页图片 CDN 404 修复
- commit `db59ccf` 被 amend 覆盖后未 push，CDN 引用失效
- `git push` + 重建原型更新 CDN hash 到 `190ed32`

### 10. 24 点后昨日穿搭残留修复
- 原型 HTML 日期在构建时硬编码（`time.strftime('%Y-%m-%d')`）
- 客户端加 `filterTodayCards()` → `DOMContentLoaded` 执行
- `new Date()` 获取真实日期，对比 `data-date`，隐藏不匹配卡片

### 11. JS 括号不匹配崩溃修复
- `filterTodayCards` 尾括号多一个 `}` → 整页 JS 崩溃
- 修复后括号 5 open / 5 close 平衡

# 单品规避规则 v2 — 最终方案

## 核心思路

```
同日 ≠ 跨日，热门 ≠ 冷门
同日可复用（用户只是换搭配方式）
跨日分级冷却（基础款快周转，特色款慢唤醒）
```

---

## Tier 1：同日规避

**原则**：用户一天内生成多套，是在"迭代搭配"，不是"构建衣橱"。衣服还在手边，完全可以复用。

**规则**：

| 当天第N次 | 行为 | Prompt 提示 |
|-----------|------|------------|
| 1 | 正常推荐 | 无 |
| 2 | 提示已有1套，建议换 ≥1 件核心单品 | `🔄 今天第2套 — 建议换掉上衣或下装或鞋子中的1件` |
| 3+ | 提示已有多套，强制换 ≥2 件（含鞋子） | `🔄 今天第3套 — 必须换掉鞋子，上衣/下装至少再换1件` |

**特殊触发词**：用户说"完全不同/换一套/别重复/不一样" → 立即升级为第3+级规则。

**Prompt 示例**：
```
📌 今天已生成 2 套（同日可复用，以下仅供参考）:
  🆕 今日穿搭: TS-001, PT-006, SHOE-006
  🆕 今日穿搭第1版: TS-005, PT-006, SHOE-006
🔄 建议至少换掉 1 件核心单品以体现变化
```

## Tier 2：跨日冷却

### 热度计算公式

```
heat_score = 穿着次数分(60%) + 适用场景分(20%) + 好评加分(20%)

穿着次数分 = min(穿着次数 / max_wears × 100, 100)    # max_wears = 衣柜最高穿着次数
适用场景分 = min(occasions数量 / 3 × 100, 100)       # 3个以上场景=满分
好评加分   = 3星次数 × 25                              # 4次=满分
```

### 三级冷却

| 等级 | heat_score | 基础冷却 | 说明 |
|------|-----------|---------|------|
| 🔥 热门 | ≥ 65 | **2天** | 基础百搭款，隔天可穿 |
| 🌤 温门 | 30-64 | **4天** | 正常周转 |
| ❄️ 冷门 | < 30 | **6天** | 特色单品，降低撞衫感 |

### 品类系数

| 品类 | 系数 | 理由 |
|------|------|------|
| 鞋子 (SHOE) | ×0.8 | 换上衣就换整体印象，鞋可连穿 |
| 下装 (PT/SH) | ×1.0 | 标准 |
| 上衣 (TS/LS/SHIRT/TANK) | ×1.2 | 最显眼，变化要大 |
| 外套 (JK) | ×1.0 | 标准 |
| 配饰 (HAT/BAG/SUN/ACC/SOCK) | ×0.7 | 复用无伤大雅 |

### 最终冷却天数

```
cooldown = base_cooldown × 品类系数 - rating_bonus（floor取整，最少1天）

rating_bonus = 该单品在3星outfit中出现的次数（上限2天）
```

### 实际计算示例

```
SHOE-009 (Nike复古高帮篮球鞋, ×10次, 多场景, 多次3星)
  热度: 100 → 🔥 热门, base=2天
  品类: SHOE ×0.8 → 1.6
  评分加成: -1天 → 0.6
  最终冷却: 1天 → 几乎隔天可穿 ✅

TS-005 (HLA米白宽松T恤, ×8次, 日常, 少量3星)
  热度: 80 → 🔥 热门, base=2天
  品类: TS ×1.2 → 2.4
  评分加成: 0 → 2.4
  最终冷却: 2天 → 一周能穿2-3次

SHOE-006 (Converse姜黄高帮帆布, ×5次, 街头/日常)
  热度: 55 → 🌤 温门, base=4天
  品类: SHOE ×0.8 → 3.2
  评分加成: 0 → 3.2
  最终冷却: 3天 → 无法连穿两天！

SHOE-007 (Timberland大黄靴, ×1次, 街头)
  热度: 12 → ❄️ 冷门, base=6天
  品类: SHOE ×0.8 → 4.8
  冷却: 4天 → 一周1-2次

JK-004 (Merrell机能外套, ×1次, 户外)
  热度: 12 → ❄️ 冷门, base=6天
  品类: JK ×1.0 → 6天
  冷却: 6天 → 一周最多1次
```

## 边界情况处理

### 新衣服（0次穿着）
- 前3次穿着不加冷却限制（鼓励尝试）
- heat_score 默认按温门计算
- 第4次起按实际数据计算热度

### 所有候选单品都在冷却中
- 选冷却剩余时间最短的，标注 "⚠️ 冷却未满但为最优选择"

### 用户指定单品（大黄靴等功能）
- 强制单品无视冷却规则

### 季节/天气覆盖
- 不适合当前天气的单品（如35°C羊毛外套）在验证阶段已被拦截
- 冷却只对天气合适的单品生效

---

## 冷门唤醒

42% 单品穿着≤3次 → 需要机制推动。

| 触发条件 | 行为 |
|---------|------|
| 冷门单品冷却期满 | 新鲜度 +15，Prompt 标注 `💡 沉睡单品` |
| 每5次推荐 | 自动触发1次"清库存模式"，优先以冷门单品为锚点 |
| 连续10次未被选中 | 新鲜度额外 +10（越久不用越推） |

---

## 衣柜表格改动

当前表头：
```
| ID | 品牌 | 颜色·面料 | 场景 | 风格匹配 | 场景适配 | 新鲜度 |
```

新表头（新鲜度 → 冷却状态）：
```
| ID | 品牌 | 颜色·面料 | 场景 | 风格匹配 | 场景适配 | 新鲜度 | 冷却 |
```

冷却列格式：`🟢可用` / `🟡3天` / `🔴2天` / `💡唤醒` / `🔄同日`

```
🔄 同日已生成（可复用）:
  🆕 今日穿搭: TS-005, PT-006, SHOE-006

📌 跨日冷却（已过冷却/冷却剩余）:
  🔥 热门: SHOE-009🟢, TS-011🔴2天, SHOE-005🟢, PT-001🟡1天, TS-005🔄同日
  🌤 温门: SHOE-006🔄同日, TS-001🔴3天, PT-006🔄同日, ...
  ❄️ 冷门: SHOE-007🟢💡, JK-004🟢💡, SHOE-011🟢💡

💡 沉睡单品（冷却已满，优先推荐）: SHOE-007, JK-004, SHOE-011

🎯 选品约束:
  1. 🔴冷却中 → 尽量不选（除非所有替代都更差）
  2. 🟡将满 → 可以选，但非首选
  3. 🟢可用 → 正常选择
  4. 🟢💡 → 优先考虑（唤醒沉睡单品 +15新鲜度）
  5. 🔄同日 → 可以复用，但至少换1件核心单品
```

## 实施步骤

### Step 1: 新增 `calculate_item_heat(item_id)` — ~30行
- 读穿着次数、场景数、3星次数
- 返回 (heat_score, heat_level)

### Step 2: 新增 `get_cooldown(item_id)` — ~25行
- 计算冷却天数
- 计算距上次穿着天数
- 返回 (status, days_since, cooldown_days)
  - status: 'available' | 'cooling' | 'almost' | 'sameday' | 'awaken'

### Step 3: 改 `build_wardrobe_table()` — ~10行
- 新增冷却列
- 同日标记 `🔄`

### Step 4: 改 `_get_freshness()` — ~10行
- 冷门唤醒 +15
- 冷却中 -10
- 连续未选 +10

### Step 5: 改 prompt 文本 — ~15行
- 增补冷却提示段
- 同日提示段

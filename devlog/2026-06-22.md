## 每日自动推荐系统 + 手机端健康检查

### 背景
用户希望每天早上 6 点自动生成穿搭，醒来打开手机页面就能看到。现有系统全靠手动触发（手机端输入"今天穿什么"），无每日自动调度。

### 方案设计（Karpathy 视角参与）
- Mac 24h 在线 → 本地调度，零额外基础设施
- 完整管线（AI 选品 → Seedream 生图 → 排版 → 重建原型）
- 手机网页为主展示面，不推微信
- 失败时手机端显示警告卡片 + 一键重试

### 实现

**1. 管线并发锁** (`wechat_control.py`)
- 新增 `_pipeline_running` + `threading.Lock` 全局状态
- `run_pipeline()` 入口检查，运行中拒绝重复请求
- 成功/失败自动更新 `_pipeline_status`

**2. 增强 /health 端点** (`wechat_control.py`)
- 原：只返回 `{"status": "ok"}`
- 现：扫描 `outfits/` 判断今日有无推荐，返回 `today_ok` / `running` / `latest_date`

**3. 手机端健康检查** (`build_prototype.py`)
- 页面加载 JS 调 `/health`：
  - ✅ `today_ok=true` → 正常 Hero 卡片
  - 🔄 `running=true` → 三点跳动加载动画 + 每 5s 轮询
  - ❌ 都 false → 琥珀色警告卡片 + 「⚡ 立即生成」按钮
- 点击按钮 → POST `/api/chat` → 轮询 task → 完成自动刷新页面

**4. Cron 调度**
- Claude Cron: `57 5 * * *` (5:57 AM，避开整点高峰)
- 命令: `curl -s -G http://localhost:8765/cmd --data-urlencode "t=今天穿什么"`
- 失败自动等 60s 重试一次
- Durable = true，持久化到 `.claude/scheduled_tasks.json`

**5. GET /cmd 修复**
- `match_command` 把"今天穿什么"映射为 `action='today'`
- 原 GET handler 只对 `('generate', 'recommend')` 启管线，`today` 被忽略
- 修复：`today` 加入白名单，映射为 `_start_async_pipeline('recommend', ...)`

## 穿搭周报系统

### 背景
用户希望每周看到穿搭评分总结，同时保留月度综合报告。服装少（76件），一个月一次报告间隔太长。

### 设计方案（Superpowers 标准流程）
- brainstorming → spec → writing-plans → 逐 Task 执行
- 手机网页展示，复用「衣橱→月度报告」入口
- 默认显示周报，底部「查看完整月度报告」切换
- 单品缩略图 + 风格穿搭图视觉化
- 每周一 8:57 Cron 预热，每月1号 8:57 Cron 预热

### 实现

**1. 数据层** (`rating_analyzer.py`)
- `filter_ratings_by_days()` — 按 outfit 目录日期前缀过滤近N天
- `generate_weekly_report()` — 轻量周报文本
- `--weekly` 命令行标志

**2. API 层** (`wechat_control.py`)
- `GET /api/report?period=weekly|monthly` — 返回含缩略图 URL 的 JSON
- `_find_report_item_thumbnail()` — CDN 优先的单品缩略图 URL
- `_find_report_style_image()` — 风格评分最高 outfit 效果图 URL
- 月报额外包含：中立模式分析 + AI 建议

**3. 展示层** (`build_prototype.py`)
- 按钮「月度报告」→「📊 穿搭报告」
- CSS: 单品卡片（缩略图56×56 + 描述），风格网格（2列），切换按钮
- JS: `loadReport(period)` 替代 `loadMonthlyReport()`，fetch `/api/report`
- 兜底：无缩略图用 👔 emoji 占位，无风格图用深蓝底+文字占位

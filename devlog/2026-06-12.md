### 二、API 替代 claude -p（下午核心重构）🔥

**问题发现：**
手机发送指令后，`wechat_control.py` 通过 `subprocess.run(['claude', '-p', prompt])` 启动新的 Claude CLI 进程，与用户 IDE 中的 Claude Code 主会话互斥冲突：
- IDE Claude 被挤掉 → 终端变粉红重启
- `claude -p` 子进程挂起 → 变成孤儿僵尸进程
- 管线永远卡在 Step 1/4

**解决方案：**
用 **doubao-seed-2.0-code API** 直接调用替代 `claude -p`，同时将所有文件操作从 AI 执行改为 Python 本地执行。

**新增函数（wechat_control.py）：**
| 函数 | 作用 |
|------|------|
| `parse_wardrobe()` | 解析服装档案.md → 76件单品 ID→文件映射 |
| `get_wardrobe_summary()` | 提取衣柜表格给 AI 做上下文 |
| `call_doubao_chat()` | 调用豆包聊天 API 做穿搭分析 |
| `extract_json()` | 从 AI 回复提取 JSON（3级回退：直接解析→代码块→花括号） |
| `execute_outfit_plan()` | Python 本地创建目录、写文件、复制图片 |

**新流程：**
```
手机指令 → 豆包API分析(JSON) → Python本地创建文件
         → Seedream生图 → composite_v2排版 → git push → 微信推送
```

**新增配置：**
- `CATEGORY_MAP` — 13个品类到 wardrobe 目录名 + 豆包生图前缀的映射
- `API_CHAT_URL` — 火山引擎 chat completions 端点
- `CHAT_MODEL` — doubao-seed-2.0-code

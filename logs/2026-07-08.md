## 一、摄影风格失效根因与修复

### 现象
连续 3 套穿搭（7/7 明日穿搭、7/8 今日穿搭两版）的 Seedream 生图都忽略场景描述（minimalist concrete-and-white gallery space），人物站在灰墙前面，光影扁平。

### 诊断
- 排除：R2 生成的 `seedream_prompt` 正确包含相机/场景/光影/姿势/情绪（字符级验证）
- 排除：`get_photo_direction` 正确匹配 `contemporary_genderless` 模板
- **根因**：`tools/generate.py` ~332 行的身份保持从句被 **硬塞到 prompt 最前面**：
  ```
  旧: [Image 1 is a reference photo... preserve identity — 最高权重]
      [Full body shot... gallery space... — 被淹没]
  ```
  Seedream 优先保留参考图的背景/光影/姿势，后面描述的场景完全被忽略。

### 修复（`tools/generate.py` ~332-359）
三处改动：
1. **插入位置**：不再 prepend，改为找到 `wearing` 关键词后在场景段之后、服装段之前插入
2. **身份指令**：新增 `Do NOT preserve the background, lighting, or pose from image 1`
3. **结构顺序**：场景（最高权重）→ 身份保持 → 服装描述
4. **兜底**：找不到 `wearing` 时匹配 `wears`/`dressed in`，全无则追加末尾

**效果验证**（`2026-07-08_今日穿搭` prompt）：
```
旧: 场景在 467/1156 (40%位置)
新: 场景在 241/1170 (21%位置) — 权重翻倍
```

## 二、服务器重启后的 UnboundLocalError

### 现象
修复后重启服务 → 所有 POST 请求报 `UnboundLocalError: local variable 'resolve_user_dir' referenced before assignment`

### 根因
`wechat_control.py` 第 6712 行（`do_POST` 方法内）有一个局部 `from common import resolve_user_dir`。Python 编译时把 `resolve_user_dir` 标记为整个方法的局部变量，导致前面第 6157 行的调用报未绑定错误。

模块顶部（第 111 行）已有 `from tools.common import resolve_user_dir`，局部 import 完全多余。

### 修复
删除第 6712 行的局部 `from common import resolve_user_dir`，使用模块级导入。

## 三、四条验证规则粒度调整

### 3.1 面料重量规则（unified_pipeline.py ~2602）
- **问题**：`is_winter_weight = fabric_weight in ('厚', '中厚', '加厚')` — 中厚牛仔布夏天正常穿
- **案例**：PT-001 浅水洗蓝牛仔被拦截，但夏天穿牛仔裤完全正常
- **修复**：`fabric_weight in ('厚', '加厚')` — 中厚放行

### 3.2 风格匹配升级为致命违规（wechat_control.py ~3512）
- **问题**：`critical_keywords = ['运动场景', '避雷品类', '禁止', '缺少']` 不含风格匹配 → SHOE-002 对 japanese_city_boy 评分 27<30 被放行
- **修复**：加入 `'风格匹配', '指定风格'`

### 3.3 ≥35°C 长袖上衣（unified_pipeline.py ~2547）
- **问题**：无差别封杀所有 LS/SHIRT，忽略女性防晒衫/空调房薄衬衫
- **案例**：nan 的 SHIRT-002 被拦截，但可能是雪纺/丝绸轻薄款
- **修复**：轻薄面料例外（雪纺/丝绸/亚麻/棉麻/真丝/蕾丝/网纱/莫代尔）

### 3.4 ≥35°C 外套（unified_pipeline.py ~2554）
- **问题**：同上，薄西装/雪纺开衫也被误杀
- **修复**：轻薄面料例外（亚麻/棉麻/雪纺/丝绸/天丝/蕾丝…）

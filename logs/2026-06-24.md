## 一、皮肤检测公式三次迭代

### 1.1 旧公式回顾（坑8，之前已修复）
```
R>95, G>40, B>20, R>G, R>B, R-G>15, max-min>15
阈值：皮肤占比 < 3% → 单品图
```
- 对鞋子/包有效，但对暖色材质（草帽/皮革/卡其布）无效

### 1.2 第二版：收紧 RGB + 色相约束（坑11）
- **根因**：草帽 RGB (147, 159, 155)，25.8% 像素 R>G，H=37°（黄橙色），真人皮肤 H=15-25°（红橙色）
- **修复**：
```python
# R 必须显著大于 G 和 B
R > G+10, R > B+10, R-G > 20, max-min > 20
# 色相 ≤ 35° 排除黄橙色材质
H <= 35
```
- **效果**：草帽 15.8% → 0.8% ✅，真人照 18-100% 保持 ✅

### 1.3 第三版：加饱和度约束
- **根因**：红色布料 (H=1.6°, S=0.621) 触发误判，真皮肤饱和度 0.1-0.55
- **修复**：加 `S >= 0.1 && S <= 0.55`
- **效果**：红色布料 4.7% → 0.4% ✅

### 1.4 最终公式
```python
_skin = (R > 95) & (G > 40) & (B > 20) & \
        (R > G + 10) & (R > B + 10) & \
        ((R - G) > 20) & (max-min > 20) & \
        (H <= 35) & (S >= 0.1) & (S <= 0.55)
```

| 材质 | 旧公式 | +H≤35° | +S约束 | 最终 |
|------|--------|--------|--------|------|
| 真人皮肤 | 15-100% ✅ | 15-100% ✅ | 15-100% ✅ | ✅ |
| 草帽(米色) | 15.8% ❌ | 0.8% ✅ | 0.8% ✅ | ✅ |
| 红色布料 | — | 4.7% ❌ | 0.4% ✅ | ✅ |

## 二、iOS Safari 图片缓存问题

### 2.1 现象
同一张图 (MD5 `62aae458`) 出现在 **9 个不同批次**中。用户只选 1 张新图，系统收到 4-8 张（新图 + 旧图缓存混合）。

### 2.2 前端修复（三层）

**第 1 层：DOM 重建**
```javascript
// 旧：复用同一个 input 元素
document.getElementById('add-album-input').click()

// 新：每次打开前销毁旧元素，创建全新 input
var old = document.getElementById('add-album-input');
if(old) old.remove();
var input = document.createElement('input');
// ... 全新属性 ...
document.body.appendChild(input);
input.click();
```
iOS Safari 的 `input.value=''` 清不掉底层文件缓存，但 `removeChild` + `createElement` 能彻底重置。

**第 2 层：客户端文件名+大小+时间戳去重**
```javascript
var key = file.name + '|' + file.size + '|' + file.lastModified;
// 5 分钟内同 key 不重复添加
```

**第 3 层：服务端同批次 MD5 去重**
```python
# 同一 task 内相同 MD5 → 跳过（不去跨批次比较）
_batch_md5s = set()
if _img_md5 in _batch_md5s: continue
```

### 2.3 去重策略演进
| 版本 | 策略 | 问题 |
|------|------|------|
| v1 | 无去重 | 旧图反复上传，触发 SegFormer |
| v2 | 服务端 30min MD5 去重 | 太激进，新图也被拦截，全部 0 张处理 |
| v3 (最终) | 前端 DOM 重建 + 客户端 key 去重 + 服务端同批次去重 | 不跨批次拦截 |

## 三、EXIF 方向校正

### 3.1 问题
上传管线的分析阶段（皮肤检测 / SegFormer / AI 识别）未做 EXIF 旋转校正。iPhone 竖拍照片存为横图 + EXIF 旋转标记，分析阶段看到的是横躺图。

### 3.2 修复
`_run_add_analysis` 中 `PILImage.open()` 后立即调用：
```python
from PIL import ImageOps as _ImageOps
_pil_img = _ImageOps.exif_transpose(_pil_img)
```
入库阶段 (`_finalize_add_item`) 已有此处理，现在分析阶段也有了。

## 五、关键经验

1. **皮肤检测不能只靠 RGB 绝对值**，必须加色相(Hue)排除黄橙色材质，加饱和度(Saturation)排除高饱和布料
2. **iOS Safari `<input type="file">` 的缓存问题**无法通过 `value=''` 解决，必须 `removeChild` + `createElement` 重建 DOM
3. **服务端去重不宜跨批次**，否则会误拦用户真正的新上传。去重主力应该在前端和同批次内
4. **EXIF 校正要在分析前做**，不仅仅是入库保存时
